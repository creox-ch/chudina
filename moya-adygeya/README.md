# «Моя Адыгея» — платформа программы лояльности

Коалиционная программа лояльности, каталог бизнеса, справочник туриста, доставка/бронирование и аудиогид Республики Адыгея.
Собрано по презентациям и документам проекта (см. «Источники»). Зависимостей нет: Node.js 22+, встроенный `http`, JSON-хранилище.

## Запуск

```bash
cd moya-adygeya
ADMIN_PASSWORD='задайте-пароль' npm start          # http://localhost:3000
SEED_DEMO=1 ADMIN_PASSWORD=... npm start           # + демо-партнёры (помечены «ДЕМО»)
npm test                                           # 25 тестов: ядро правил и сквозной API
```

| Переменная | Назначение |
|---|---|
| `ADMIN_PASSWORD` | пароль оператора (логин `operator`, меняется через `ADMIN_LOGIN`). Если не задан, пароль генерируется и печатается в лог при первом запуске |
| `APP_SECRET` | ключ подписи токенов. Если не задан, генерируется при каждом запуске (все сессии сбрасываются при перезапуске) |
| `SEED_DEMO=1` | добавить демо-партнёров и их логины `demo1`…`demo4` (пароль `demo-pass-123`) |
| `DATA_FILE`, `PORT` | путь к файлу данных (по умолчанию `data/db.json`, в git не попадает) и порт |

Ключи терминалов партнёров печатаются в лог один раз при активации.

## Что реализовано

**Участник (гость)** — `#/account`
- регистрация по телефону и паролю, выдача карты (16 цифр, начинается с 9) и реферального кода;
- подтверждение телефона кодом из SMS (Правила 3.1.5, 6.2): начисление работает сразу, списание — только после активации;
- баланс, история операций, заказы с отменой, обращения (предложение/жалоба).

**Каталог и справочник** — `#/catalog`, `#/partner/:id`, `#/reference`
- карточки партнёров с поиском по категории и ставкой начисления; позиции и заказ с бронированием по дате;
- отзывы (только от зарегистрированных участников, публикуются после модерации оператора);
- справочник объектов и аудиогид (плеер появляется, когда указана ссылка https).

**Партнёр** — `#/cabinet`
- сальдо взаиморасчётов, операции, заказы (подтвердить → выполнить/отменить), позиции, кампании, новости (публикуются после проверки оператором).

**Оператор** — `#/admin`
- обзор: участники, бонусы начислены/списаны/непогашены, комиссии, воронка подключения;
- партнёры: чек-лист по четырём этапам, перевод на следующий этап, тариф, ставка начисления, возмещение, ключ терминала, приостановка;
- взаиморасчёты, обращения (статус, ответ, скрытие), новости, справочник, аудиогид, очередь уведомлений, калькулятор тарифа, аннулирование неактивных.

**Терминал партнёра (API)** — кассовое ПО или виртуальная касса:
- `POST /api/terminal/identify` — заголовок `X-Terminal-Key`, тело `{"identifier": "карта или телефон"}`;
- `POST /api/terminal/sale` — `{"identifier", "checkAmount", "bonusAmount", "itemIds"}`: списание части чека бонусами и начисление на весь чек.

## Бизнес-правила (`src/ledger.js`)

| Правило | Источник | Реализация |
|---|---|---|
| 1 бонус = 1 ₽ скидки, без денежного выражения | Правила 1.9, 5.17, 2.18 | все суммы в целых рублях, бонусы — учётные единицы |
| Начисление на полную сумму покупки, скидка от бонусов базу не уменьшает | Правила 5.2, 5.15 | `accrue` и `sale` считают бонус от `checkAmount` |
| Ставка начисления партнёра 2–20% | презентация «Бизнес-модель» | `bonusRateBp` 200–2000 bp, ставка по сегментам — подсказка из xlsx |
| Списание сначала бонусами этого партнёра, затем FIFO | Правила 6.13 | `redeem` сортирует лоты: свой партнёр → старейшие |
| Комиссия оператора 0,5–1% от чеков | презентации, тарифы | `feeBp` из тарифа, начисляется на каждое начисление |
| Возмещение партнёру за принятые бонусы 100% (или 97,5%) | схемы расчётов, xlsx `089bb85b` | `reimbursementBp` по партнёру |
| Партнёр, выпустивший бонусы, возмещает их оператору | схемы расчётов | записи `bonus_issued` → сальдо партнёра |
| Бонусы за счёт оператора (акции) не входят во взаиморасчёт с партнёрами | `operator_funded` | реферальный бонус оплачивает оператор |
| Кампании: первая покупка, n-я покупка в месяце, сумма чека, товар, день рождения, дни недели | xlsx `b0101274` | `campaignMatches` |
| Пакетная скидка: 3 партнёра −10%, от 4 −20% | презентация «Стоимость участия» | `quoteSubscription` |
| Реферальный бонус — после первой завершённой покупки реферала | маркетинговая акция «приведи друга» | `rewardReferrerIfEligible`, один раз на участника |
| Бонусы неактивных более года аннулируются | Правила 2.11 | `expireInactive` (запускается кнопкой в кабинете оператора) |
| Этапы подключения партнёра: переговоры → тех. аудит → договоры → интеграция | схемы «Этап 1–4», методика 302a21d9 | `config.js`, чек-лист, `advance` |

Инвариант, который проверяют тесты: сумма чистых обязательств партнёров = комиссии − бонусы за счёт оператора. Оператор не «теряет» бонусы при взаиморасчётах.

## Допущения и отклонения (нужно подтвердить с оператором)

1. **Тарифы** взяты из презентаций 2018 года (`cc07d3b3`, `9bd47266`). Значения 3/6/12 месяцев понимаются как сумма за период. В 2020-х презентациях цены могут отличаться — сверить.
2. **Идентификация участника** — только полный номер карты или полный телефон. Правила 4.1 допускают последние 4 цифры телефона; при этом они неоднозначны, поэтому не реализованы.
3. **Отложенное начисление** до 40 дней (Правила 5.9) не моделируется: бонусы начисляются сразу.
4. **Заказ:** бонусы резервируются при создании, списываются и начисляются только при статусе «выполнен». Так отмена не требует возвратов.
5. **Комиссия** считается от суммы чека (презентация), а не от суммы бонусов (альтернативная схема №1 из xlsx) — переключается отдельно, сейчас не реализовано.
6. **Операторский бонус по акции «приведи друга»** — 100 бонусов, значение условное.

## Что не реализовано (вне этого этапа)

- Реальная отправка SMS и e-mail: уведомления складываются в очередь (видна в кабинете оператора).
- Приём платежей (эквайринг, онлайн-оплата доставки); оплата заказов — наличными или картой у партнёра.
- Виртуальная касса и интеграция с КПО партнёров: есть API терминала, но не готовые коннекторы.
- AR-гид и аудиогид с реальным контентом (сейчас один заглушечный объект в разработке).
- Построение маршрутов, бронирование номеров в гостиницах, курьерская логистика.
- Партнёрская MLM-механика «приведи партнёра» (в презентации — только воронка продаж).
- Выпуск пластиковых карт, печать и логистика карт.
- Мобильные приложения iOS/Android (интерфейс адаптивный, можно обернуть как PWA).
- Правовые ограничения из `c6547c68`: квалификация бонусов как способа определения цены, проверка на отклонение цен более 20% (ст. 40 НК РФ). Условия программы и формулировки в Правилах нужно согласовать с юристом; код этого не проверяет.
- Проверка возраста участника 16+ (Правила 1.6): только чекбокс в форме регистрации.
- Масштабирование: хранилище — один JSON-файл, подходит для пилота, не для нагрузки. Миграция на PostgreSQL — следующий шаг.

## Безопасность (что сделано и что нет)

- Пароли — scrypt; токены — HMAC-SHA256 с сроком 7 дней; роли гость/партнёр/оператор разделены.
- Ключи терминалов хранятся как SHA-256 и показываются один раз.
- Списание бонусов без подтверждённого телефона запрещено (403).
- Запросы к API ограничены 100 КБ; пути статики проверяются на выход за пределы `public/`.
- Не сделано: ограничение частоты входа (rate limit), CSRF-защита (токены в заголовке, не в cookie — риск низкий), аудит-лог действий оператора.

## Структура

```
src/
  ledger.js   бизнес-правила: начисление, списание, заказы, взаиморасчёты, аннулирование
  config.js   этапы подключения, категории, ставки по сегментам, типы кампаний
  server.js   HTTP API, роли, терминал, раздача public/
  store.js    хранилище в JSON-файле (атомарная запись)
  auth.js     пароли, токены
  seed.js     начальные данные (новости и аудиогид из презентаций, демо по запросу)
public/       SPA на чистом JS: index.html, app.js, styles.css
test/         ledger.test.js (правила), api.test.js (сквозные сценарии)
```
